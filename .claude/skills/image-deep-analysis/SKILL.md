# 画像多分野解析 → JSON

対象画像を「実測レイヤー」と「目視レイヤー」の2段で解析し、
`references/schema.md` のスキーマに沿った単一 JSON を出力する。
目的は、画像の中で起きていることを物理・幾何・色彩・意味のすべての層で
構造化データにすること。印象論の散文ではなく、根拠を持てる値の集合を作る。

## 手順

### 1. 対象画像の確定

- 添付画像、またはメッセージ中のパスを対象にする。複数枚あれば 1 枚ずつ同じ手順で解析し、
  画像ごとに別の JSON を出す（勝手に 1 つのオブジェクトへ混ぜない）。
- コンタクトシートやコラージュも「1 枚の画像」として扱う。内訳（各コマ）の解析が
  必要なのはユーザーがそう求めたときだけ。
- パスが不明・画像が開けないときだけユーザーに確認する。

### 2. 実測レイヤー（スクリプト実行）

最初に計測スクリプトを実行し、客観値を得る（リポジトリルートから）:

```bash
python3 .claude/skills/image-deep-analysis/scripts/measure_image.py <画像パス>
```

PIL が無い環境なら `uv run` で同じスクリプトを実行する（先頭に PEP 723 メタデータあり）。

得られる値 — 寸法・アスペクト比・EXIF・ICC・主要色・輝度/彩度統計・3x3 輝度グリッド・
エッジ強度・対称度など — は JSON の該当フィールドへそのまま採用する。
**実測値を目視の推定で上書きしない。** 逆にスクリプトが失敗しても解析は中止せず、
実測系フィールドを null にして目視だけで続行し、その旨を `confidence_notes` に書く。

### 3. 目視レイヤー（Read で画像を開く）

Read ツールで画像を実際に開き、`references/schema.md` のフィールドを上から順に
1 つずつ埋めるつもりで観察する。全体の印象でまとめて書かず、各値について
「画面内のどこを見てそう判断したか」を言える状態で記入する。
特に光（光源の方向・硬さと影の整合）、遠近（消失点と地平線）、材質（反射の性質）は
画面内の証拠から逆算する分野なので、観察→根拠→値の順を崩さない。

### 4. 出力規約

- 出力は ```json ブロックの**単一オブジェクト**。スキーマのキーと並び順を保つ。
- 実測値（スクリプト / EXIF 由来）は正確な値。それ以外はすべて推定であり、
  各セクションの `confidence`（0〜1）に確度を反映する。
- 判断できない項目は **null**。値の捏造はこのスキルの最悪の失敗で、
  もっともらしい嘘の混じった JSON は全体を信用できなくする。空欄は誠実さの表明。
- 位置は左上原点の正規化座標（0〜1）、角度は度、色温度はケルビン、距離はメートル。
- 記述値は日本語を基本とし、定訳のある技術用語（golden hour, rule of thirds, bokeh 等）は
  英語のままでよい。英語で欲しいと言われたら全記述を英語にする。
- 「幾何だけ」「色と光だけ」のような粒度指定があれば該当セクションだけ出す。
  その場合もセクション内部の形は崩さない（後で機械的に合成できるように）。

### 5. 人物・プライバシーの扱い

- 実在人物の特定・同定はしない。人物は外見属性（見た目の年齢層・髪・服装・ポーズ・表情）
  としてのみ記述する。推定年齢はあくまで「見た目の印象」であり、そう明記された
  フィールドにしか書かない。
- EXIF の GPS は、スクリプトが存在有無（`gps_present`）だけを返す。座標そのものは
  ユーザーが明示的に求めた場合のみ別途抽出する（解析結果の JSON は共有される
  可能性があるため、既定で位置情報を混ぜない）。

### 6. 保存

既定ではチャット出力のみ。「保存して」と言われたら `<画像名>.analysis.json` を
画像と同じディレクトリ（または指定先）に保存する。

## 参照ファイル

- `references/schema.md` — 全フィールド定義と記入基準。**解析のたびに読む**（記憶で埋めない）。
- `references/example-output.json` — 実画像 1 枚を本手順で解析した完全な出力例。
  粒度・文体・null の使い方の基準として最初の 1 回は目を通す。
