見た目の偏りが出るかを確認する。偏りがあればプロンプトを修正し、6〜12枚規模で再確認する。

生成には Codex の組み込み画像生成を使用した。すべて参照画像なしの新規生成。

## 3. 1ブロックのままチャット層で選択

この時点の改善版は、ユーザーが貼る文面を1ブロックに保ったまま、次の順で処理する。

1. ChatGPT / Gemini などのチャットAIが、8枚の完成カードから1枚だけをサイレント抽選する
2. 過去画像が見える場合は、8枚をシャッフルバッグとして扱い、使用済みカードを除く
3. チャットAIは「選択カード本文＋共通条件」だけを画像生成ツールへ渡す
4. 画像生成ツールは1枚だけ作り、カード番号や説明は表示しない

ユーザー側で番号、seed、レーン、別プロンプトを指定する必要はない。
同じコードブロックを、同じ会話で毎回そのまま貼る。

## 4. シード式の監査

変更前の式は、全スロットへ同じ `SEED + n * 7` を使っていた。
このため候補数が同じスロット間に固定相関が生まれた。

- 8項目スロットでは `B=I`、`D=M` が常に成立
- 10項目スロットでは A・C-2・G が固定した位置関係になる
- 全組み合わせは `SEED mod 2520` の2,520通りで一巡
- 同じシードから3案を作る規則に案番号がなく、3案の非重複指定と衝突
- 無効値を「最も近い番号」へ直す規則は、同距離時の扱いがなく再現不能

修正版は、有効候補を先に絞ってから状態を進め、その候補内の位置を選ぶ。
複数案でも状態を初期化しないため、1つのシードから別の案を再現可能にした。

## 6. 骨格カード＋小さな可変要素

完成カードだけでは、カードが再登場したときに同じ顔・髪色・瞬間・質感へ戻りやすい。
そこで、場所・服・撮影距離・髪型・主動作・光・フィルム系統は8枚の骨格カードで固定し、
カードを選んだ後にだけ次の4軸を追加抽選するハイブリッド版へ変更した。

- A 顔立ち: 4種
- C 髪色: 4種
- R 撮る瞬間: 3種
- T フィルム／光学表現の効き方: 2種

1カードあたり `4 × 4 × 3 × 2 = 96` 通り、8カード全体では768通りの
ラベル付き組み合わせになる。ただし、遠景では顔差が読めないなど、
768通りがそのまま768種類の見た目になるわけではない。

ユーザーが貼るコードブロックは引き続き1つだけ。チャットAIが骨格カードとA/C/R/Tを選び、
候補一覧や未選択カードを含めず、具体記述へ展開済みの最終プロンプトだけを
低レベル画像モデルへ渡す。

## 結論（8カード・旧4軸時点）

- 直接投げ版は1ブロックを維持する。ユーザーに別プロンプトやレーンを選ばせない。
- 8カード全部を低レベル画像モデルへ渡さず、チャットAIが骨格カード1枚とA/C/R/T各1つへ絞ってから画像生成する。
- 同じ会話で同じブロックを繰り返すと、過去画像を使ったshuffle bagで即時反復を抑えられる。
- 同一カード3枚でも、マクロ骨格を保ったまま顔・髪色・瞬間・質感の差を目視できた。
- 遠景では顔差が判定不能になり、動作中／動作後も静止画では差が縮むため、追加4軸は補助的な幅として扱う。
- すべての方式で自然なカラー写真を固定し、白黒・モノクロ・グレースケールは採用しない。
- 赤い光漏れと色付きの画面端モヤは候補から外し、今回の追加10枚でも再発しなかった。
- 厳密な再現性が必要なメタプロンプト側では、修正済みの明示seed方式を使う。

このハイブリッド方式は、1ブロック直投げという制約の中では、
カード間混合を防ぎながら同じカード内の反復も減らせる実用的な妥協点になった。
ただし、今回も小規模なスモークテストであり、真の一様乱数や画像モデル全体の
母集団分布を証明するものではない。過去画像を参照できない新規会話では、
初回選択に偏りが残り得る。

## 9. Card1再偏りとSUMMER10-BAG-v3（2026-07-31）

10カード化後も、1ブロック・サイレント抽選版からCard1が高頻度で出るという
実利用上の報告があった。報告画像は、プール＋大きな入道雲、
ストライプのボートネックTシャツ＋白ショーツ、正面寄りの全身環境構図、
高いポニーテールがそろっており、カード混在ではなくCard1そのものの再選択だった。

![利用時に再発したCard1](./silent-selector-v3/00-user-reported-card1-repeat.png)

過去の検証でも、全カードを低レベル画像モデルへ渡したときはCard1が3/4、
旧サイレント版の新規コンテキスト初回はCard1が2/4だった。
旧版の「等確率として内部抽選」「偏りなく並べ替え」は実乱数源ではなく、
同じ会話での直前重複には効いても、新規会話の先頭選好を除けなかった。

当時の版は抽選器を `SUMMER10-BAG-v3` とし、1ブロックを維持したまま次へ変更した。

1. カード本文を評価する前に、番号だけを確定する。
2. 同じ会話では各カードの使用回数を数え、最少使用回数のIDだけを候補にする。
3. 実行可能な乱数機能があれば、本文を渡さず数値配列だけから選ぶ。
4. 乱数機能がなく履歴がある場合は、非逐次の固定巡回で最少使用候補を選ぶ。
5. 履歴も乱数もない場合は、8桁の非公開チケットを剰余へ変換する。
   これは先頭選好を拡散するフォールバックであり、新規会話間の一様性は保証しない。
6. 画像生成ツールへ渡す直前に、選択カード1枚の3アンカーだけがあり、
   未選択候補や抽選指示が残っていないことを検査する。

## 10. Google Flow / ChatGPT一発生成の再検証（2026-08-01）

実利用では、Google FlowやChatGPTの新規チャットへ②を毎回1回だけ貼ると、
Card1のプール、ボーダーTシャツ、白いショーツ、高いポニーテールが高頻度で再発した。
9節の6枚は、実行環境の乱数で先にIDを決め、選択済み1カードだけを画像生成へ渡した
回帰テストであり、ユーザーの実際の一発入力を再現していなかった。

同じ静的プロンプトには外部エントロピーがない。チャット層が抽選手順を実行せず、
ブロック全体を画像モデルへ渡す経路では、暗号学的乱数、履歴、非公開数字、剰余、
カードIDを文章で要求しても真の抽選にはならない。さらに、完成カード方式では
一つの選択偏りが場所・服・髪・構図・光のすべてへ同時に広がる。

そこで旧抽選器を削除し、最初の`random/inline-random.md`と同じ構造へ戻した。

- 顔、体型、髪、シーン束、カメラの5リストだけにする
- シーン束は服・場所・動作・光だけを一組にし、髪と撮影距離は別軸にする
- 乱数、使用回数の累積履歴、固定巡回、多桁チケット、状態数の表記を置かない
- 白黒禁止と赤・橙・マゼンタのモヤ禁止は末尾へ1回だけ置く
